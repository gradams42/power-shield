PROTOCOL R1-FDIA: If Voltage magnitude sensors on Relay 1 (R1-PM1:V, R1-PM2:V, R1-PM3:V) show fluctuations exceeding 10% while the corresponding impedance sensor (R1-PA:Z) remains flat and no corresponding current spike is observed on R1-PM4:I through R1-PM6:I, the likely cause is a False Data Injection Attack (FDIA) targeting Relay 1 phasor measurements. Cross-reference R2 voltage readings for system-wide consistency. Remediation: Lock Relay 1 data stream from SCADA write access; manually verify phasor data at the R1 substation; if discrepancy with R2 persists beyond 30 seconds, escalate to control center and flag for cybersecurity review.

PROTOCOL R2-FDIA: If Voltage magnitude sensors on Relay 2 (R2-PM1:V, R2-PM2:V, R2-PM3:V) fluctuate more than 10% while impedance (R2-PA:Z) and current sensors (R2-PM4:I through R2-PM6:I) remain stable, the likely cause is a False Data Injection Attack (FDIA) localized to Relay 2. The absence of impedance change distinguishes this from a real fault. Remediation: Isolate R2 data stream; cross-reference voltage readings with adjacent Relay 1 and Relay 3; do not trip the breaker based solely on R2 voltage data until physical verification is complete.

PROTOCOL R3-FDIA: If Voltage magnitude sensors on Relay 3 (R3-PM1:V, R3-PM2:V, R3-PM3:V) show anomalous fluctuations exceeding 10% with no corresponding change in R3 current sensors or apparent power (R3:S), the likely cause is a False Data Injection Attack (FDIA) at Relay 3. Remediation: Cross-check R3 phase angle harmonic readings (R3-PA1:VH through R3-PA3:VH) against R4 for phasor consistency; if mismatch is confirmed, lock R3 voltage inputs and escalate to cybersecurity team.

PROTOCOL R4-PM: If Voltage magnitude sensors on Relay 4 (R4-PM1:V, R4-PM3:V) show fluctuations exceeding 10% during an Attack classification, the likely cause is a False Data Injection Attack (FDIA). Remediation: Manually override the automated breaker logic and verify phase angles at the substation.

PROTOCOL RTCI-01: If current magnitude sensors on any relay (R?-PM4:I, R?-PM5:I, R?-PM6:I) drop abruptly to near-zero simultaneously while voltage sensors remain nominal, AND relay_log or snort_log entries spike at the same timestamp, the likely cause is a Remote Tripping Command Injection (RTCI) attack. The combination of current collapse without a corresponding voltage sag or fault signature, plus IDS log activity, distinguishes this from a real line trip. Remediation: Do NOT re-energize the line automatically. Block all remote trip commands at the substation HMI immediately. Dispatch a field crew to physically verify breaker state. Restore line energization only after physical inspection confirms the line is clear and breaker integrity is verified. File a security incident report.

PROTOCOL RSCA-01: If impedance sensor (R?-PA:Z) drifts to a new stable value representing a change greater than 15% from the prior baseline, AND the impedance harmonic sensor (R?-PA:ZH) shows simultaneous distortion, while voltage and current magnitudes remain within normal bounds, the likely cause is a Relay Setting Change Attack (RSCA). An attacker has modified the relay protection threshold settings, which changes the measured impedance characteristics without any physical grid change. Remediation: Immediately compare current relay protection settings to the baseline configuration backup stored in the SCADA historian. Restore relay settings from the known-good configuration snapshot. Audit all remote access logs for unauthorized configuration changes in the preceding 24 hours. Do not rely on the affected relay for fault protection until settings are verified.

PROTOCOL FREQ-01: If frequency sensor (R?:F) on any relay falls below 59.5 Hz or rises above 60.5 Hz, AND the frequency derivative sensor (R?:DF) shows a rate-of-change exceeding 0.1 Hz/s, a frequency deviation event is in progress. If all four relays (R1:F, R2:F, R3:F, R4:F) show the same drift simultaneously, this indicates a system-wide generation-load imbalance or a real fault condition. If the deviation is isolated to one or two relays while others remain at 60 Hz, suspect False Data Injection on the frequency measurement channel. Remediation for system-wide deviation: Activate under-frequency load shedding relays per standard operating procedure; notify ISO/RTO. Remediation for isolated deviation: Lock affected relay frequency inputs from control logic; flag sensor as compromised; continue monitoring with adjacent relays.

PROTOCOL CURR-01: If one or more current magnitude sensors (R?-PM4:I, R?-PM5:I, R?-PM6:I) on a relay read greater than 150% of rated load current, AND phase imbalance between the three current channels exceeds 10%, a current anomaly is detected. Check control_panel_log for an automatic trip signal. If a trip signal is present and voltage has dropped, this is a natural overcurrent or short-circuit event — allow protective relay to operate normally. If no trip signal is present and voltage remains nominal, suspect a current injection attack or sensor fault. Remediation for natural fault: Allow auto-trip and follow standard line fault restoration. Remediation for suspected injection: Compare current readings against adjacent relay current sensors; if discrepancy is confirmed, isolate affected current inputs.

PROTOCOL PHASE-01: If phase angle harmonic sensors (R?-PA1:VH, R?-PA2:VH, R?-PA3:VH or R?-PA4:IH, R?-PA5:IH, R?-PA6:IH) show a sudden step-change greater than 20 degrees while the corresponding voltage and current magnitude sensors remain unchanged, the likely cause is a phasor measurement injection or GPS timing spoofing attack. Real electrical events always produce correlated changes in both magnitude and phase; a phase-only step change is a strong indicator of data manipulation at the PMU measurement layer. Remediation: Cross-check affected relay phasor angles against all adjacent relays. If the step-change is isolated to a single relay, assume PMU compromise; flag that relay as untrusted and escalate to the cybersecurity team for GPS signal verification.

PROTOCOL FAULT-01: If voltage magnitude sensors on a single relay (R?-PM1:V, R?-PM2:V, R?-PM3:V) drop more than 50% simultaneously while current magnitude sensors (R?-PM4:I, R?-PM5:I, R?-PM6:I) spike more than 200% on the same relay, this is consistent with a natural short-circuit fault on the line protected by that relay. The simultaneous large voltage collapse and current surge is the classical fault signature and is distinct from an injection attack where one measurement type changes without the other. Action: Allow the protective relay to auto-trip the faulted line. Verify fault is cleared before initiating reclose. Follow the standard line fault restoration procedure. Check control_panel_log for trip confirmation.

PROTOCOL DEGR-01: If a single sensor (e.g., R4-PM3:V) shows a slow, linear drift of less than 0.01 units per minute while all other sensors on the same relay remain steady, this is Software or Sensor Degradation. Action: Schedule recalibration; do not trip the breaker.

PROTOCOL DEGR-02: If three or more sensors on the same relay show simultaneous slow drift over multiple consecutive measurement windows, while sensors on the other three relays remain stable, the likely cause is a relay firmware failure or communication module degradation affecting the entire relay unit. This is distinct from DEGR-01 (single sensor) and from an attack (which typically shows sharper, non-linear changes). Action: Schedule immediate relay maintenance during the next available outage window. Do not use the affected relay for automatic protection decisions. Monitor trend for 24 hours and escalate if drift rate increases.

PROTOCOL EXPECTED-09: Rapid voltage fluctuations on all R1 and R4 sensors during the 08:00 or 17:00 hour windows are Expected Issues due to peak-load switching. Action: Log as routine; no intervention needed.
